A browser where typing an address loads a webpage **generated by an LLM** instead
of fetched over HTTP. Links, search boxes, forms and tabs work: every navigation
generates the next page, with session context (Referer, browsing history) passed
along so the simulated internet stays coherent. The only real network connection
the app makes is to the LLM endpoint you configure.

Version 3 is a native application written in Rust: AppKit on macOS, GTK4 with
libadwaita on Linux, Win32 on Windows (experimental), each rendering pages with
the system webview (WebKit, WebKitGTK, WebView2). No Electron, no Node, no
bundled browser engine: the macOS app is under 4 MB.

## Install

Download from [Releases](https://github.com/nettsundere/llmouser/releases):

| Platform | File | Notes |
|---|---|---|
| macOS 11+ (Apple silicon) | `LLMouser-<version>-macos.dmg` | Not notarized. If macOS says the app is damaged, run `xattr -d com.apple.quarantine /Applications/LLMouser.app` once. |
| Ubuntu 24.04+ (x64) | `llmouser_<version>_amd64.deb` | `sudo apt install ./llmouser_<version>_amd64.deb` pulls GTK4, libadwaita and WebKitGTK 6.0. |
| Windows 10/11 (x64) | `LLMouser-<version>-windows-x64.zip` | **Experimental.** Unzip and run `LLMouser.exe`. Needs the [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/), present on any up-to-date Windows. The Windows shell is built and type-checked in CI but not yet verified by hand; report issues. |

Open **Settings** (Cmd/Ctrl+,) and configure your LLM:

| Provider  | Default endpoint              | Example model      |
|-----------|-------------------------------|--------------------|
| OpenAI    | `https://api.openai.com/v1`   | `gpt-4o`           |
| Anthropic | `https://api.anthropic.com`   | `claude-sonnet-5`  |

Enter your API key (stored locally, never shown again), save, and type an address
like `google.com`. Plain words search through the search URL set in
Settings → UX (`{query}` is replaced by the text). Settings saved by the previous
Electron versions are picked up automatically on first run.

## Using it

- **Address bar**: `example.com` gets `https://`; `best cat food` searches.
- **Links, forms, JavaScript navigation** inside a generated page all generate
  the next page. Nothing is ever fetched from the real internet.
- **Back / Forward** restore the exact page you saw, without regenerating.
- **Stop** (the Go button while loading, or Cmd/Ctrl+.) cancels a generation.
- **Tabs**: on macOS every tab is a native window tab (Cmd+T new, Cmd+W close,
  Cmd+Shift+T reopen, Cmd+N new window). On Linux and Windows the window has a
  tab strip with the same shortcuts on Ctrl; closing the last tab leaves a fresh one.
- **Save Page as PDF…** (Cmd/Ctrl+S) exports the page silently to a file you
  choose; **Save Page as HTML…** (Cmd/Ctrl+Shift+S) keeps the generated source.
- **Errors** show a page with the exact message, Try Again, and Open Settings for
  credential problems. Without an API key, navigation fails fast with guidance.
- **Language**: English, Russian, Chinese; switching in Settings → UX
  retranslates everything on screen at once.

## Configure the universe

Settings → **Universe rules** describes the universe all generated sites exist in.
The default is our real universe. Rewrite it to change everything:

> A universe where the Soviet Union still exists and humanity grows stronger and happier

Save, navigate anywhere: sites, brands, news and search results now follow your
rules. Clear the field to restore the default.

## Build

All automation is Rust: `cargo xtask <command>` (see `crates/xtask`).

### Prerequisites

| Platform | Needed to build and run |
|---|---|
| macOS 11+ | Rust 1.85+, Xcode Command Line Tools |
| Ubuntu 24.04+ | Rust 1.85+, `sudo apt install libgtk-4-dev libadwaita-1-dev libwebkitgtk-6.0-dev` |
| Windows 10/11 | Rust 1.85+ (MSVC), Visual Studio Build Tools (`rc.exe`), WebView2 Runtime |

### Run from source

```bash
git clone https://github.com/nettsundere/llmouser.git
cd llmouser
cargo run --release                 # the app for this platform
LLMOUSER_MOCK=1 cargo run           # offline: deterministic mock "internet", no key needed
```

### Packages

```bash
cargo xtask build                   # everything below
cargo xtask build macos             # build/macos/LLMouser.app + LLMouser-<v>-macos.dmg   (on macOS)
cargo xtask build linux             # build/linux/llmouser_<v>-1_amd64.deb                (Docker)
cargo xtask build windows           # build/windows/LLMouser-<v>-windows-x64.zip          (native or cargo-xwin)
```

- `macos` uses only Apple's stock tools (`sips`, `iconutil`, `codesign` ad-hoc, `hdiutil`).
- `linux` builds inside the image from `packaging/linux/Dockerfile` (Ubuntu 24.04,
  `linux/amd64`) with `cargo deb`; needs Docker. The first run downloads and
  compiles everything, later runs reuse a cached cargo registry volume.
- `windows` runs `cargo build --release` on Windows. On macOS/Linux it
  cross-compiles with `cargo xwin` (`cargo install cargo-xwin`, plus Homebrew
  `llvm` for `clang-cl`/`llvm-rc` and `lld` for `lld-link`; without `lld` the
  task symlinks rustup's `rust-lld` as `lld-link`). Icon and manifest are
  embedded either way (`packaging/windows/`).

## Test

```bash
cargo xtask test                    # everything below, in order
cargo xtask test unit               # browser crate + shell unit tests (any OS)
cargo xtask test macos              # E2E against the native macOS app (on macOS; windows open on screen)
cargo xtask test linux              # E2E against the GTK app under Xvfb in Docker (any OS with Docker)
cargo xtask test windows            # on Windows: E2E against the Win32 app; elsewhere: type-check only
cargo xtask lint                    # cargo fmt --check, clippy -D warnings, cargo audit, cargo deny
cargo xtask coverage                # llvm-cov (unit + E2E) → coverage/{lcov.info,html,summary.txt}
```

Plain cargo works too: `cargo test -p llmouser-browser` (unit) and
`cargo test -p llmouser --test e2e` (E2E for the current platform).

### How the E2E suite works

The 64 specs in `crates/app/tests/e2e` launch the real application and drive
its native widgets (toolbar items, menus, dialogs, tabs) through an automation
socket the app opens only when `LLMOUSER_E2E_PORT` is set. The same specs run
against all three shells. Each test gets a fresh app with:

| Variable | Effect |
|---|---|
| `LLMOUSER_MOCK=1` | deterministic offline provider instead of a real LLM |
| `LLMOUSER_DATA_DIR` | isolated settings directory (never imports old Electron settings) |
| `LLMOUSER_SAVE_PATH` | stubs the native save dialog: a path, or empty for "cancel" |
| `LLMOUSER_E2E_PORT` | TCP port of the automation channel (`127.0.0.1` only) |

No network, no keys, no external drivers. Tests run one app at a time.

Status per platform:

| Shell | Unit | E2E | Where |
|---|---|---|---|
| macOS (AppKit) | pass | 64/64 | locally on a Mac |
| Linux (GTK) | pass | 64/64 | Docker + Xvfb (`cargo xtask test linux`); containers need `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1`, set by the task, because WebKit's bubblewrap sandbox needs user namespaces |
| Windows (Win32) | pass | needs a Windows machine | WebView2 has no headless mode and does not run under Wine; CI type-checks and cross-builds the shell |

CI (`.github/workflows/ci.yml`) runs lint, unit and E2E on Ubuntu, macOS and
Windows runners, and uploads the coverage report. Coverage (unit + E2E, macOS)
is 96% of lines; the report is committed in `coverage/`.

## How it is built

`crates/browser` is the browser itself minus pixels: tabs, history, navigation,
the LLM providers that play the role of the internet, settings and translations.
It forbids `unsafe`. `crates/app` holds the three native shells and the E2E
suite. The design philosophy (TRIZ for the architecture, Nielsen's heuristics for
the interface) and the rules for contributing are in [AGENTS.md](AGENTS.md).

## Security

- Generated pages run inside the system webview under a strict Content Security
  Policy (no remote resources, no fetch/XHR/WebSocket), and every real network
  request is additionally blocked at the webview level (WebKit content rules on
  macOS and Linux, WebView2 resource filtering on Windows). Every navigation a
  page attempts is cancelled and regenerated by the LLM instead.
- The API key is stored in the settings file only and never leaves the browser
  crate; the UI just learns whether a key exists.
- Dependencies are permissively licensed (MIT/Apache/BSD family, enforced by
  `cargo deny`; no GPL, LGPL or MPL crates) and audited with `cargo audit` in CI.
